# MirrorShard 2のAI機能について  
MirrorShard 2では、様々な機能においてAIの支援を受けることができます。  
現在、  
・メインエディタ  
・AIチャットウィンドウ  
・アイデアプロセッサ  
・OpenCodeウィンドウ（要OpenCodeインストール）

# 1. AIの導入方法  

## Geminiの場合  

1. Google AI Studioへのログイン: Googleアカウントで、Google AI Studio にアクセスします。  
2. APIキーの取得:  
　・画面左側の「Get API key」をクリックします。  
　・「Create API key in new project」でAPIキーを生成し、その文字列をコピーしておきます。  
　※APIキーは他人に知られないよう、厳重にご注意ください。  
3. MirrorShardの設定:  
　・設定ウィンドウで「AI設定」タブを選択し、「Gemini API Key」欄にコピーしたAPIキーを貼り付けてください。

## Groqの場合  
Groqは、Groq.Incが開発・運営している対話型生成AIです。無料でAPIキーを取得することができ、従来のAIに比べて回答の生成速度が極めて高速なことで知られています。  
※xAI社の「Grok」ではありません。お間違えのないようご注意ください。  

1. Groqへのログイン: GoogleアカウントなどでGroqにログインします。
2. APIキーの取得: 画面右上の「API Keys」をクリックしてAPIキーを取得します。  
　※出現したAPIキーは一度しか表示されませんので、コピーして保存しておいてください。
　※APIキーは他人に知られないよう、厳重にご注意ください。
3. MirrorShardの設定:  
　・設定ウィンドウで「AI設定」タブを選択し、「Groq API Key」欄にコピーしたAPIキーを貼り付けてください。

## Cerebrasの場合  
CerebrasはアメリカのAI企業で、AIの学習と推論に特化した独自の超巨大チップを開発しています。  
その自社製チップを用いたAPIサービスは非常に高速で、軽量モデルを選択したときには毎秒2000〜3000トークンもの速度で回答を生成します。  

1. Cerebrasへのログイン: 公式サイトの右上にある「GET STARTED」を押し、GoogleアカウントなどでCerebrasにログインします。  
　※名前の入力を求められます。
2. API keysタブを開くと、すでにDefault Keyが作成されていますので、コピーボタンを押してクリップボードにコピーします。  
3. MirrorShardの設定:  
　・設定ウィンドウで「AI設定」タブを選択し、「Cerebras API Key」欄にコピーしたAPIキーを貼り付けてください。  

## OpenRouterの場合  
OpenRouterは、様々なAIモデルを提供するクラウドAIサービスです。  

1. 公式サイト
https://openrouter.ai  
にアクセスし、画面右上のSign inボタンを押して、Googleアカウントなどでログインします。
2. Create API Keyボタン、あるいは右上のKeysからAPIキーを作成します。  
Nameは自分のわかりやすい名前にし、Credit limitには金額の上限を記入します。Creditsメニューからクレジットを追加しない限り課金されませんので、無課金の場合は空欄でOKです。
3. 作成したAPIキーをコピーします。一度しか表示されないので注意してください。
4. MirrorShardの設定:  
　・設定ウィンドウで「AI設定」タブを選択し、「OpenRouter API Key」欄にAPIキーを貼り付けてください。  

## Cohereの場合  
Cohereはカナダのスタートアップ企業で、自然言語処理に優れたAIモデルを展開しています。  

1. 公式サイト
https://cohere.com/  
にアクセスし、メールアドレスかGoogleアカウントでアカウントを作成します。  
2. 画面右上の「サインイン」ボタンなどからDashboardに入り、画面左のパネルから「API Keys」を選択します。
3. Trial keyが最初から作成されていますので、目のマークを押してキーを表示し、クリップボードにコピーします。
4. MirrorShardの設定:  
　・設定ウィンドウで「AI設定」タブを選択し、「Cohere API Key」欄にコピーしたAPIキーを貼り付けてください。  

## Mistralの場合  
Mistralはフランスの企業で、同社のAIは欧州の文化と学習データを背景にした個性を持ちます。また無料枠が大きいので、チャットなどで気軽に運用することができます。  
認証に電話番号が必要なことと、データの学習への同意を求められる点にご注意ください。  

1. 公式サイト  
https://mistral.ai/
を開き、Googleアカウントなどでユーザー登録します。「Create your team」と言われますが、適当な名前をつけておけば大丈夫です。  
2. 右上の「Try Studio」からAI Studioに入り、画面左のパネルから「API Keys」を選択します。
3. 「Add a new key」を選択してキーを作成します。
4. 利用プランの設定を求められますので、お好みのプラン（無課金の場合は「Experiment」）を選択します。
5. 電話番号の入力を求められます。たとえば日本の電話番号で090から始まる場合、+81 90 ……となります。
6. APIキーを作成し、コピーしてMirrorShardの設定ウィンドウの当該箇所に貼り付けます。 

## ローカルAIを使用する場合  

### LM Studioの場合  

1. LM Studioの準備:  
　・LM Studioを起動し、左メニューの「開発者」タブを開きます。  
　・お好きなモデルをロードします。（モデルをお持ちでない場合は、「探索」タブからダウンロードしてください）  
　・左上隅の「Status:Stopped」と書かれているボタンをクリックしてサーバを起動します（「Status: Running」になります）。  
　・その右の「Settings」から「CORSを有効にする」を有効にします。  
　・画面右側のパネルから「Context」タブを選び、システムプロンプトを記入すると、より望む出力結果が得やすくなります。  

２. MirrorShardの設定:  
　・初期設定のままローカルホストで運用する場合には、そのまま（Endpoint URL: http://127.0.0.1:1234/v1/chat/completions のまま）で設定完了です。
　・LANでアクセスする場合にはLM Studio側の設定（Server Settings）で「ローカルネットワークで提供」をオンにし、MirrorShard側の設定ウィンドウで「AI設定」タブを選択しで、「EndpointURL」のIPアドレスをご自身の環境に合わせて書き換えます。  

### Ollamaの場合  

Ollamaはコマンドラインベースですが、軽量で動作が安定しているローカルLLM実行環境です。  

    Ollamaの準備:  
    ・公式サイト ( https://ollama.com/ ) からOllamaをダウンロードしてインストールします。  
    ・ターミナル（PowerShellやコマンドプロンプト）を開き、使いたいモデルをプル（ダウンロード）します。  
    例: ollama pull gemma2 または ollama pull llama3  
    ・Ollamaは通常、バックグラウンドで自動的に起動しています（タスクトレイにアイコンがあります）。  

    MirrorShardの設定:  
    ・設定ウィンドウの「AI設定」タブを開きます。  
    ・Endpoint URL: http://127.0.0.1:11434/v1/chat/completions と入力します。（ポート番号がLM Studioとは異なります）  
    ・Model Name: ターミナルでプルしたモデル名を入力します（例: gemma2 や llama3:latest）。※ここが間違っていると動きません。  
    ・「適用」を押して保存します。  

これでOllamaとの対話が可能になります。  

※その他、koboldcppなどのローカルAI実行環境でも動作します。  

# 2. AIの選択と切り替え  

## AIの切り替え（メインエディタ）  
サイドバーのタブ一覧上部にあるAIセレクターで、メインエディタが使用するAIを切り替えられます。  
※AIチャットウィンドウやアイデアプロセッサの設定とは独立して保持されます。 

## AIの切り替え（AIチャットウィンドウ）  
画面左上のAIセレクターから、使用するAIを選択します。  

## AIの切り替え（アイデアプロセッサ）  
右上のボタン群の下にあるAIセレクターからAIを選択します。  

## Geminiのモデル選択
設定ウィンドウの「Model」欄の右にあるプルダウンメニューから、使用するモデルを選択できます。  
「Model」欄にモデル名を直接入力することで、それ以外のバージョンのGeminiを使うことも出来ます（後述）  

## 他クラウドAIのモデル選択  
Geminiとほぼ同じです。  
使用可能なモデルの一覧は、  
https://console.groq.com/docs/models　（Groqの場合）  
など、各社のドキュメントを御覧ください。  

## Geminiの長所と注意点  
長所：導入が比較的容易な上に非常に高性能  
注意点：通信に時間がかかるため生成が遅いこと、使い方によっては課金が必要になること、データが学習に用いられる可能性があること、Googleの厳格なポリシーに違反する使い方は出来ないこと  

## Gemini 3.1 Pro などの最新モデルへの対応について  
設定画面の「Model」欄で「手動入力」を選択、モデル名を直接入力することで、gemini-3.1-pro-preview などの最新モデルを指定することも可能です。  
【重要：料金について】  
デフォルトの選択肢（Gemini 3.1 Flash-Lite Preview等）は無料枠（Free Tier）に対応していますが、カスタム設定で指定可能な最新モデルには無料枠が提供されていない場合があります。  
Google Cloudで課金を有効にしているアカウントでこれらのモデルを使用すると、API利用料が発生する可能性があります。ご利用の際はGoogleの料金プランを十分にご確認ください。  

## Groqの長所と注意点  
長所：導入が比較的容易、Geminiほどではないが高性能、生成が非常に高速、クラウドAIのため低スペックPCでも高速な回答生成が可能、原則としてデータを学習しない  
注意点：クラウドに送信する以上セキュリティには注意が必要、Geminiよりは性能が劣る、使い方によっては課金が必要になる、入力や回答にはポリシーによって制限がかかる  

## ローカルAIの長所と注意点  
長所：ローカルで運用できるためデータが学習されないこと、十分なマシンスペック（特にグラフィックボード）があればGeminiに較べてレスポンスがかなり高速なこと、多様なモデルを使い分けられること、課金が不要なこと、ポリシーが緩いこと  
注意点：導入が比較的複雑なこと、Geminiに較べて性能が劣ること、低スペックなマシンではGeminiより却って遅くなること、LM Studio（またはOllama）を常駐させておかなければならないのでメモリ消費量が増えること  

## AIの使い分け  
MirrorShardは多様なAIに対応しており、用途によって使い分けが可能です。一例として、  
・高精度な回答が欲しい　→　Gemini  
・高速な応答が欲しい　→　Groq・Cerebras  
・学習データが英語圏に偏っていないAIがいい　→　Mistral  
・いろいろなAIを試してみたい → OpenRouter  
・データを学習されたくない、企業製AIの厳しいポリシーから自由になりたい　→　ローカルLLM  
　……など。

# 3. 各機能の使い方   

## ■ メインエディタ統合型AI機能の使い方   
MirrorShard 2 v1.1.0以降、これまでの「AIチャットウィンドウ」に加え、エディタ本体から直接AIを呼び出して文章作成やコーディングをサポートする機能が追加されました。  

### 1. AI執筆支援（続きを書く）  

小説やドキュメントの執筆中、次に続く文章をAIに提案させる機能です。  

    操作方法: 執筆中、続きを書きたい位置にカーソルを置き、Alt + Enter を押します。  
    
    中断: ESCキーを押すと中断できます。  

    挙動: カーソルより前の文章（ローカルAIは1000〜100000字、Geminiは最大1000〜4000字）をAIが読み取り、その文脈や文体に合わせて続きの文章を自動的に追記します。  

    ※コンテキスト長（AIに読み取らせる文字数）を大きくしすぎると、AIの応答が遅くなります。また、ご使用のAIの最大コンテキスト長を超えるトークンを送るとエラーになります。通常は2000〜3000程度をお勧めします。  
    ※ブラウザでChatGPTやGeminiなどの商用AIを使う場合（AI側でコンテキストを保持している）と異なり、MirrorShardのAI機能はリクエストのたびにコンテキストを送信する仕様です。そのため、必要なコンテキストの長い文章（長編小説など）の続きを書かせたりするような用途には向いていません。  

### 2. Missing Link Completion（前後の文章をつなぐ）      

カーソル位置の前後をつなぐ文章を提案させる機能です。  

    操作方法: 執筆中、文章を挿入したい位置にカーソルを置き、Alt + Shift +Enter を押します。  
    
    中断: ESCキーを押すと中断できます。  

    挙動: カーソル位置の前後の文章をAIが読み取り、その文脈や文体に合わせて文章を自動的に挿入します。  


### 3. 選択範囲のAI加工（要約・リライト・翻訳・プロンプト生成・画像生成）  

エディタ上のテキストを選択し、右クリックメニューから特定の加工を依頼する機能です。結果は選択範囲の直後に挿入されます。  

    操作方法: テキストを範囲選択し、右クリックメニュー から以下の項目を選択します。  

        AI: 翻訳 (Translate): 選択範囲を任意の言語に翻訳します。  

        AI: 要約 (Summarize): 実行時に目標文字数を指定するダイアログが表示されます。長大な文章を簡潔にまとめたい時に便利です。  

        AI: リライト (Rewrite): 文意を変えずに、より分かりやすい表現や洗練された文体に書き換えます。  

    中断: ESCキーを押すと中断できます。  

    特徴:  

        メインの設定（Max Tokens）を無視して長文の出力を許可する設定になっています（最大8192トークン）。  

        元の文章を残したまま直後に追記されるため、AIの回答を比較・検討しながら編集できます。  

        AI: 画像生成プロンプトを作成: 選択範囲の文章から、画像生成AIに適した英文プロンプトを作成します。  

        AI: 画像を生成: 選択範囲の文章をもとに画像を生成し、画像保存フォルダ（設定ウィンドウで指定）に保存したのち、カーソル位置に画像リンクを作成します。マークダウンプレビュー（Ctrl+M）を開くと、その場で画像を確認することができます。

		画像の生成には、Stable DiffusionもしくはMistral Agentsを使用します。

		・Mistral……設定画面の「ビジュアライズ (画像生成) に使用するAI」で「Mistral Agent」を選び、エディタのAIセレクタを「Mistral」にします。  

		・Stable Diffusion……「ビジュアライズ (画像生成) に使用するAI」で「Stable Diffusion」を選びます。

### 4. AIコード補完（コードエディタモード限定）  

「コードエディタモード（Ctrl + K）」の時のみ動作する、プログラミング専用の補完機能です。  

    操作方法: コードの記述中、Alt + Enter を押します。  

    挙動: 「FIM (Fill-In-The-Middle)」という技術を用い、カーソルの前後のコードを解析して、その中間に収まるべき最適なコードを推測して挿入します。  

    推奨モデル:  

        qwen2.5-coder:7b (または 1.5b / 3b) などのコーダー特化モデル。  

        ※通常の対話型AIや「思考型（Thinking）」モデル（qwen3-thinkingなど）では、コードの解説を始めてしまうため正常に機能しない場合があります。

    制限事項:  

        ・プロジェクト全体のファイル構造はスキャンしません。現在開いているファイルのコンテキストのみを参照する軽量仕様です。  
        ・本機能はローカルLLM専用となります。Gemini等クラウドAIでのコード補完はできません。詳しくは次項を御覧ください。  

#### ⚠️ コード補完機能の動作要件（ローカルAI限定）  
コードエディタモードにおける「コード補完（Alt+Enter）」は、FIM（Fill-In-The-Middle）という特殊な推論技術を使用するため、**Local AI専用の機能**となっています。  
※メインエディタのAIセレクターが「Gemini」になっていても、コードモード中の補完は強制的に Local AI の設定（URLおよびモデル）を参照して実行されます。  

この機能を利用するには、設定画面の「Code Editor Settings」にて、ローカルAIのエンドポイントと、コーディングに特化したモデル（qwen2.5-coder等）を正しく設定しておく必要があります。  

## ■ AIチャットウィンドウの使い方  

　メインエディタのUIボタン（またはCtrl+Shift+A）で、AIと自由に対話できる専用のチャットウィンドウを開きます。執筆中の相談相手として、キャラクターのロールプレイ相手として、あるいは、TRPGのセッションログのように、AIとの対話そのものを楽しむこともできます。  

### 基本的な使い方  

- メッセージの送信: 画面下部の入力エリアにテキストを入力し、「送信」ボタンかCtrl+Enterを押します。  
- UIボタン（括弧内は対応ショートカット）:  
    - ログのクリア（Ctrl+Shift+C）: 現在のチャットログをクリアします。  
    - 保存（Ctrl+S）: 現在のチャットログを「名前を付けて保存」します。  
    - 別名保存: ファイルに名前をつけて保存します。  
    - 読込（Ctrl+O）: 過去に保存したチャットログ（MirrorShard独自形式, LM Studio形式, Gemini形式に対応）を読み込みます。  
    - 最大化（Win・Linux:F11　Mac:Cmd+Ctrl+F）: ウィンドウを最大化/元に戻します。  
    - 閉じる（Ctrl+Shift+A）: ウィンドウを閉じます。  
- 右クリックメニュー: ウィンドウ内を右クリックすると、ログの保存/読込のほか、コピー/ペーストなどの便利な機能にアクセスできます。
    - チャットログを直接メインエディタに送ることも出来ます。送ったデータは新規テキストファイルとして開かれます。  

### 対話のコントロール  

各メッセージの横に表示されるボタンで、対話を細かくコントロールできます。  
- 編集 : ユーザーのメッセージを編集し、そこからAIの応答を再生成させます。  
- 削除 : そのメッセージ以降の、すべての対話履歴を削除します。  
- 再生成 : AIの応答に満足できない場合、同じ文脈で、もう一度別の応答を生成させます。  
- コピー : AIの応答を、クリップボードにコピーします。  

### 名前とアイコンのカスタマイズ  

ユーザーとAIの表示名は、設定タブで変更することが出来ます。  
また、ユーザーやAIにアイコンを設定することもできます。アイコンには任意の画像ファイルを設定することができます。  

### AIチャットウィンドウの画像生成機能  

AIチャットウィンドウでは、AIに「画像を生成して」と頼むだけで画像を生成することができます。  

ただし画像の生成にはMistral Agaentsの設定、またはStable Diffusion Web UIのインストールが必要になります。

#### Mistral Agentsの場合

1. Mistralにログインし、AI StudioのAgentsタブでAgentを作成します。
2. Capabolitiesの項目でAddを押し、「Image」を使用可能にします。
3. MirrorShardの設定画面で「Mistral Agent ID」（MistralのAgents画面から確認可能）を入力し、「Mistral Agentsを有効にする」のチェックボックスをオンにします。
4. AIチャットウィンドウのAIセレクタを「Mistral」にします。

#### Stable Diffusionの場合

Stable Diffusionを使用すれば、任意のAIで画像生成が可能になります。

1. Stable Diffusion Web UI（A1111、Forge、Forge Neo、stable-diffusion.cppなど）をインストールします。
2. MirrorShardの設定画面にある「Stable Diffusionの起動スクリプト」に、起動時に使用するファイル（webui-user.batなど）を登録します。
3. 起動時に使用するファイルをテキストエディタで開き、COMMANDLINE_ARGS= の行に --api と追記します（後述）。
4. Ctrl+Shift+WでStable Diffusionを起動します（標準ブラウザが開きます）。  
　※sd-cli（stable-diffusion.cppのCLIモード）を指定している場合、このステップは不要です。
5. AIチャットウィンドウを起動し、送信ボタンの上の「SD-Link」ボタンを有効にします。
6. チャット欄に「〇〇の画像を生成して」などと入力して送信すれば、画像が生成されます。  
　※このときStable diffusionが起動していないと、エラーになります（sd-cli以外）。

なお、Stable Diffusionの利用に関してはいくつかの注意点があります。詳細は後述の「5. 画像生成機能について」の「Stable Diffusion使用上の注意点」の項目をご参照ください。

### 検索機能

ヘッドレスブラウザ「Obscura」を使うことにより、AIにWeb検索をさせたり、URLを指定して読み込ませたりすることができます。  

1. Obscura(https://github.com/h4ckf0r0day/obscura)をダウンロードして任意のフォルダに展開します。
2. MirrorShardの設定ウィンドウで「AI設定」タブを開き、Obscuraのパスを入力します。
3. AIチャットウィンドウで「Search」ボタンを有効にします。
4. AIに検索を指示すると、AIがObscuraを起動してWeb検索を開始します。
標準ではDuckDuckgoによる検索を行うようになっていますが、Tavily（後述）を使用することで、より高精度の検索を行うことができます。  

#### Tavily

Tavilyは、AIにWeb検索をさせるためのサービスです。月に1000リクエストまで無料で利用できます。  
Tavilyを使用して検索する場合は、APIキーの取得が必要になります。  

1. [Tavilyのサイト](https://tavily.com/)にアクセスし、右上のSign Upからアカウントを作成します。  
2. アカウントを作成すると、自動で「default」という名前のAPIキーが生成されますので、そのキーをコピーします。
3. MirrorShardの設定画面を開き、「AI設定」タブの「Tavily APIキー」に貼り付け、「Tavilyで検索する」のチェックボックスをオンにします。

上記の手順を行うことで、AIチャットウィンドウの左上にある検索エンジンセレクタに「Tavily」のメニューが表示されます。

#### 検索機能の注意事項

1. CerebrasとCohereはエージェント機能がうまく働かないので、検索機能の使用はできません。
2. Mistral Largeもエラーを返すことが多く、使用は非推奨です。Gemini等他AIをご利用ください。
3. ローカルAIを使用する場合、性能の低いモデルではうまく動作しない場合があります。  
軽量モデルでもGemma 4 E4Bなどは正常に動作するため、Gemma系が比較的相性が良いかと思われます。
4. 本機能は簡易的なもので、検索・情報分析とも商用ツールほどの精度はありませんので、そのあたりはあらかじめご了承ください。  
5. Macの場合、ObscuraがGatekeeper（MacOSのセキュリティ機能）にブロックされてしまうことがあります。その場合、ターミナルで以下のように入力して実行を許可してください。

xattr -d com.apple.quarantine "（Obscuraのパス）/obscura"

例えば「アプリケーション」フォルダにインストールしている場合、

xattr -d com.apple.quarantine "/Applications/obscura"

となります。

## ■ アイデアプロセッサのAI機能  
現在、アイデアプロセッサには4種類のAI機能があります。

### 1. AFA（AI Free Assosiation: AIによる自由連想機能）  
ノードを１つ選択して「Activate AI」ボタン（あるいはCtrl+Shift+F）を押すと、そのノードから連想される３つの文章をAIが生成します。  

### 2. IP Missing link  
リンクを選択してAIボタンまたはCtrl+Shift＋Fを押すと、  
・リンクの両端のノード  
・リンクラベル  
・線種  
をAIが読み取り、ノードとノードの間を埋める文章を生成します。生成させる項目（キャラクター、アイデアなど）は、起動時に出現するダイアログで指定することができます。  
※モデルによってエラーが出る場合は、AI連想機能応答長を長めに設定してください。  

### 3. Node Alchemy  
ノードを範囲選択してAIボタンまたはCtrl+Shift＋Fを押すと、選択範囲内のノードの内容をAIが読み取り、それらを踏まえた内容のノードを生成します。生成させる項目は、起動時に出現するダイアログで指定することができます。  
※モデルによってエラーが出る場合は、AI連想機能応答長を長めに設定してください。  

### 4. Template Completion  
物語のテンプレート（Story Archetype）のコンテンツテキスト（ノードを右クリックすると出現するテキスト）編集中にのみ使用可能な機能です。  
コンテンツテキスト編集中に「Activate AI」ボタン（あるいはCtrl+Shift+F）を押すと、  
・テンプレート全体のストーリー構成  
・カーソル位置の直前の文章  
をAIに送り、AIはそれを参考にして文章を生成します。  
これにより、少ない文字数で効率よく物語の全体構造をAIに伝えられるため、より精度の高い文章生成をすることが出来ます。

## 注意点

### Mistral使用上の注意点

Mistralが無課金で生成できる画像は1ヶ月に数枚程度です。本格的な利用には課金が必要になります。  

### Stable Diffusion使用上の注意点

1. AI機能で使用するためには、あらかじめStable DiffusionをAPIモードで起動しておく必要があります。

ご利用の環境の起動ファイル（Windowsは webui-user.bat、Mac/Linuxは webui-user.sh 等）をテキストエディタで開き、起動オプションに --api を追記してください（※念のため、起動ファイルのバックアップをとることをお勧めします）。

例: 

set COMMANDLINE_ARGS=--api (Windows) 

export COMMANDLINE_ARGS="--api" (Mac/Linux)

「COMMANDLINE_ARGS=」の行に他の記述がある場合は、先頭に「--api」を挿入してください。

例：

　　export COMMANDLINE_ARGS="--uv"

→　export COMMANDLINE_ARGS="--api --uv"  

※stable-diffusion.cppの場合は、--apiの追記は必要ありません。  
※stable-diffusion.cppのCLIモード（sd-cli）を指定している場合は、事前に起動しておく必要はありません。ただし、起動のたびに毎回モデルをロードしますので、連続で画像生成する場合にはServerモード（sd-server）をご利用ください。  
※Serverモードを使用する場合は、Web UI同様にCtrl+Shif+Wでの起動が必要になります。

2. 画像生成の際の使用モデルはStable Diffusion側で指定されたものになりますが、Animaなど特殊なモデルでは生成に失敗することがあります。

 - 上記のような場合は他のモデルを使用するか、あるいは右クリックメニューの「AI: 画像生成プロンプトを作成」で選択範囲のテキストをプロンプトに翻訳し、Stable Diffusion本体で画像を生成してください。
 - stable-diffusion.cppの場合はMirrorShard側でモデルを指定しますが、本エディタの機能ではテキストエンコーダもVAEも指定できないため、やはり特殊なモデルでは使用できません。

3. チャットからの画像生成（SD-Link）機能は、AIが「ユーザーの指示をStable Diffusion用の英語プロンプトに翻訳し、特定の書式に整形して出力する」ことで実現しています。
そのため、**「指示に忠実な、賢いAIモデル」**を使用しないと正しく機能しません。

    推奨モデル（クラウド）: Gemini、Groq (GPT-OSS)、Mistral-large 等

    推奨モデル（ローカル）: Gemma系など、指示に忠実なモデル（※ローカルモデルの場合、PCスペックによっては回答生成と画像生成の二重負荷がかかるため動作が遅くなる場合があります）

指示追従能力の低いモデルでは、プロンプトを日本語で出力してしまったり、指定のフォーマットから外れてしまったりすることがあります。できるだけ高性能なモデルをお使いください。  

※ただしMistralの場合、Agents機能が有効になっているとAgents機能での画像生成が優先されてしまう可能性があります。MistralでSD-Linkを使用されるときは、Agents機能のチェックボックスをオフにしておいてください。  

4. 当然ながら、Stable Diffusionを運用するためにはそれなりのPCスペックが必要になります。

基本的には、NVIDIA製の独立したグラフィックボード（VRAM 12GB以上推奨）が必要になります。

最軽量クラスのモデルを使えばGTX1050Ti（4GB VRAM）搭載機や最小構成のMac Mini（16GBユニファイドメモリ）でも十分実用可能ではありますが、さすがにIntelなどのオンボードグラフィックス（一般的な事務用PCなど）では正常に動作しません。  

5. Stable Diffusionをインストール・展開するフォルダのパスには、**絶対に** 「日本語（全角文字）」や「スペース」を含めないでください。正常にパスが解決されず、エラーになります。

もし日本語パスでインストールしてしまった場合は、インストール手順を最初からやり直してください。Stable Diffusionのフォルダ内にある venv（Python仮想環境）は、作成された場所の絶対パスを記憶するため、単純にStable Diffusionを別のフォルダやドライブに移動させると、壊れて起動しなくなります。

※stable-diffusion.cppの場合は日本語名のフォルダでも使用可能なようにしてありますが、基本的には避けたほうが無難です。

6. Macでstable-diffusion.cppを使用する場合、GPU（Metal）が十分活用されずに画像生成が低速になる場合があります。その場合はForge Neoなどをお使いください。
 
また、起動ファイルやlibstable-diffusion.dylibがGatekeeper（MacOSのセキュリティ機能）にブロックされてしまうことがあります。その場合、ターミナルで以下のように入力して、フォルダ内すべてのファイルの実行を許可してください。

xattr -d com.apple.quarantine "（フォルダのパス）"

例えばフォルダが「書類 (Documents)」内の「sd-cpp」である場合、

xattr -d com.apple.quarantine "~/Documents/sd-cpp/"

となります。

## ⚠️ AI機能（GeminiなどクラウドAI使用時）の利用料金について  

以下ではGeminiを例に挙げて説明しますが、他のクラウドAIでも同様です。  

AIチャット機能でGeminiを選択した場合、Google社の Gemini API を使用することになります。  
APIの利用料金は、**ユーザーご自身のGoogleアカウントおよびGoogle Cloudプロジェクトの契約状況**に依存します。  

*   **無料枠（Free Tier）での利用:**  
    *   クレジットカード情報を登録していない、または課金設定を無効にしている場合、無料枠の範囲内で利用可能です。  
    *   無料枠の上限に達した場合、APIはエラーを返し、それ以上の利用はできなくなります（勝手に課金されることはありません）。  
*   **従量課金（Pay-as-you-go）での利用:**  
    *   Google Cloudプロジェクトで課金を有効にしている場合、無料枠を超えた利用分や、無料枠の対象外である高性能モデル（Gemini 3系など）の利用に対して、**Google社から料金が請求される可能性があります。**  

**【免責事項】**  
APIの利用に伴い発生した料金について、本ソフトウェア開発者は一切の責任を負いません。  
ご利用の際は、必ず [Google Gemini APIの料金ページ](https://ai.google.dev/pricing) やGroqの料金プラン（https://console.groq.com/settings/billing/plans）などをご確認の上、ご自身の判断でモデルの選択や利用頻度の調整を行ってください。  

## [APIキーの取り扱いについて]  
・APIキーは、あなたのアカウントに紐づく「秘密の鍵」です。他人に知られないよう、厳重に管理してください。  
・万が一APIキーが第三者に流出した場合、あなたの無料利用枠が不正に消費されたり、予期せぬ問題が発生したりする可能性があります。  

## [AI切り替え時のコンテクスト（文脈）について]  
　AI使用時、チャットの場合はログの全体がコンテクストとしてAIに送られます。  
　ローカルLLMの中にはセンシティブなコンテンツ（暴力行為、NSFWなど）に対する制約の緩いものもありますが、たとえばセンシティブな内容のコンテクストをうっかりGeminiに送ってしまったりした場合、Googleの利用規約に抵触して思わぬ事態が発生する場合があります。  
　ご利用の際には、接続先が間違っていないか十分ご確認ください。  

## ログビューアとして使う際の注意点  
　本機能はGoogle AI studioやLM Studioで生成したログを閲覧するビューアとして使うことも出来ますが、読み込めるログの長さには限界があり、数十万トークンあるような長大なログを読み込むとフリーズしてしまいます。  
　こうした長大なログを閲覧する際には、AIチャットウィンドウではなくメインエディタの右クリックメニューから「Geminiログをインポート」を選択し、メインエディタで閲覧されることをお勧めいたします（ただしGemini形式のみ対応）。  
　メインエディタの心臓部であるエディタライブラリ「CodeMirror」は巨大テキストの扱いに強く、数十万トークン程度なら問題なく読み込めます。  

## AIの生成した回答が途中で切れてしまう場合  
　AIの応答長を短く設定した場合などに、ローカルAIの返答が途中で切れてしまうことがあります。  
　これは、AIモデルの指示追従能力が低いために字数内で内容を要約することができず、知っている情報をすべて出力しようとしてしまった結果、MirrorShard側の文字数制限に引っかかって途中で回答が終わってしまうことによって発生します。  
　このようなケースでは、ローカルAI側でシステムプロンプトや応答長の設定をすると改善される場合があります。たとえばLM Studioの場合、「開発者」タブの右側にあるパネルで、「Context」タブや「Inference」タブから各種設定を行ってください。  

## Gemini 2.5 Flash 等で回答が極端に短くなる場合  
　Gemini 2.5 Flash / Pro などのモデルや、一部のローカルLLM（推論強化モデルなど）を使用している際、回答が極端に短くなってしまうことがあります（特にメインエディタのAI執筆機能の使用時）  

### 原因  
　これらのモデルは、回答を出力する前に内部で**「思考（Thinking）」**を行うプロセスが含まれる場合があります。  
設定画面の「最大応答長」で指定した数値は、この「思考」に使われるトークンも含んだ上限値として扱われます。  
　そのため、設定値が少ない（例: 500～1000程度）と、AIが思考しただけでトークンを使い果たしてしまい、肝心の回答を出力する前に制限に達して強制終了してしまうことがあります。  

### 対策  
**「最大応答長」の値を大きく設定してください。**  
　Gemini 2.5 Flash等を使用する場合は、**3000 ～ 5000** 程度、あるいはそれ以上の値に設定することを強く推奨します。  
（Geminiの思考プロセスは毎回発生するとは限りませんが、余裕を持った設定にしておくことで防ぐことができます）  

　※ローカルLLMにおいても、思考過程を出力するモデルを使用する場合は同様の現象が起きるため、長めの設定が必要です。

# 8. 設計思想  
本エディタは「ユーザーが明示的に要求するまでAIには何もさせない」という思想のもと設計されています。  
したがって、ユーザーが送信処理を行った瞬間にのみ、必要最小限のコンテキストを送信する仕様になっています。このため、バックグラウンドで常に執筆内容を監視・送信し続けている商用AIエディタに比べて、どうしても回答の待ち時間が長くなりますが、それは応答速度よりもユーザーの主体的選択とプライバシー、PCのリソース（CPU/メモリ）を優先しているからです。
